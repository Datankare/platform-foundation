# ADR-047: Multimodal Provenance & Synthetic-Media Detection

Status: Proposed (Phase 5 Sprint 6). Decision maker: Raman Sud.
Related: ADR-014 (observability), ADR-044 (multimodal input $\u2014 detect-in), ADR-045 (governed image generation $\u2014 emit-out), ADR-046 (multimodal content safety). `platform/ai/instrumentation.ts`, `platform/agents/trajectory-store.ts`.

---

## 1. The end state

Synthetic-media identity is handled as **one concern seen from both directions**: we **emit** verifiable provenance on everything we generate, and we **detect** synthetic origin on everything we ingest. Provenance-out is a durable, signed credential attached at commit; detection-in is a probabilistic **risk signal**, never a standalone gate. This is the platform's ability to "distinguish AI images across the board."

## 2. Decisions

**D1 $\u2014 Emit: a signed provenance credential on every generated image.** At ADR-045 commit, each image carries a **C2PA content credential** (signed, tamper-evident: generated by us, when, which model) plus an invisible watermark. The credential is a **schema-validated structured output** (P6) $\u2014 attaching it is part of commit, so an image without provenance is never surfaced. It is recorded on the trajectory (P3/P18).

**D2 $\u2014 Detect: synthetic origin on input is a risk signal, not a gate.** Image/audio arriving through ADR-044 is classified for synthetic origin. Detection is **probabilistic and adversarial**, so a positive verdict **raises the ADR-045/046 risk tier or routes to the governed path** $\u2014 it **never** hard-blocks on its own. Treating a fallible detector as a gate would both over-block genuine content and give false assurance; as a _signal feeding the governed path_, it strengthens the decision without being trusted absolutely.

**D3 $\u2014 One seam, both directions.** Emit (for ADR-045) and detect (for ADR-044) are the same provenance/identity seam exposed two ways; both are recorded on the durable, inspectable trajectory (P18). ADR-044 consumes `detect`; ADR-045 consumes `emit`. Neither reimplements it.

**D4 $\u2014 Provenance is verifiable, not decorative.** The emitted credential is independently checkable (signature + watermark), so a downstream party $\u2014 or our own detect path on a round-trip $\u2014 can confirm our authorship. Verifiability is the point: a credential that cannot be checked is not provenance.

## 3. Alternatives considered

(a) **Detection as a hard input gate** $\u2014 rejected: fallible + adversarial; hard-gating on it over-blocks and creates false confidence. Risk-signal into the governed path is the honest use.

(b) **Watermark only, no C2PA** $\u2014 rejected as sole mechanism: a watermark survives some transforms but is not a signed, human-legible provenance record. C2PA + watermark together give tamper-evidence _and_ resilience.

(c) **Provenance attached post-hoc, outside commit** $\u2014 rejected: an image could surface before it is credentialed. Attaching at commit (ADR-045 D5) is the only order with no gap.

## 4. Conformance (L21)

A provenance/detection kit:

- every committed generation carries a **verifiable** credential (signature checks; watermark present);
- an image **without** a credential never surfaces (attachment is part of commit);
- the inbound detector produces a **signal that raises tier / routes to governed** $\u2014 the kit asserts it **never** hard-blocks alone;
- emit + detect verdicts are **recorded on the trajectory**.

## 5. GenAI / RAMPS / WCAG

- **Support:** P6 (the credential is a schema-validated structured output), P3/P18 (recorded + inspectable), and it **enables** P4 (the detection signal feeds screening/tiering) and P17 (the credential is part of the commit).
- **RAMPS:** provenance is a compliance + trust primitive; detection strengthens safety without being a single point of false trust.
- **WCAG:** provenance metadata travels with the image's description contract; it does not replace alt-text.

## 6. Consequences

- ADR-045 attaches the credential at commit; ADR-044 attaches the detection signal on input $\u2014 both consume this one seam.
- Establishes C2PA as the platform's provenance standard, extensible to audio/video provenance later without a new decision.
- Deferred: cross-organisation provenance verification (checking _others'_ credentials as a trust input) and audio watermarking $\u2014 additive on the same seam.
