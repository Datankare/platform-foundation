# Audit register — October 2026 whole-system adversarial review

**Reviewed:** platform-foundation `develop` 2c94596 and its first consumer, 2026-10-21. **How:** nine
independent auditors that did not build the code — eight static, one per scope (identity,
administration and governance, agents and AI, content safety and moderation, data layer, product
services, plumbing and operations, supply chain and sync), each applying all eight rings of the
[brief](BRIEF.md); one dynamic (about 5,600 hostile requests against a production build: 41 routes,
four kinds of caller, 2,500 random-sequence steps). Critical and High findings were re-verified
against the code before entry. **Tracked as** [TASK-145](../TASKS.md).

**What held.** Under the dynamic run no anonymous, forged-token or guest caller got a single success on
any admin, moderation or AI route; spoofed forwarding headers did not lift rate limits; no internal
detail, secret or personal data appeared in an error body; mass-assignment fields were ignored. Guest
tokens, SSO (state and PKCE), delegation-token verification, the rate limiter, coded errors and the
outbound-call surface were sound. The perimeter held; the failures were inside it.

**The five patterns** behind most findings: controls built and tested but never called; second paths to
an effect with weaker checks; placeholder identities that broke the controls built on them (audit rows
and approvals silently not written); fail-open defaults (in-memory stores, swallowed boot errors,
fire-and-forget security writes); and controls that depended on lists nobody verified. Each pattern now
has a check that runs — see [ASSURANCE.md](../ASSURANCE.md).

**Disclosure.** Fixed findings are described in full. Open findings are described without exploit detail
until they are fixed ([SECURITY.md](../../SECURITY.md)); the auditors' raw reports are not published.
